## Decisión

El almacén de objetos S3 de la plataforma (exportaciones, habilidades, adjuntos y eventos de Langfuse) en desarrollo, SaaS y bundle on-premise es Silo (pgsty/silo), fork de MinIO mantenido por Pigsty que conserva la API S3, las variables MINIO__, las rutas /minio/_, el formato de datos y el cliente (mcli), con la release fijada en cada entorno. Se retira la imagen de MinIO porque el proyecto upstream está archivado desde abril de 2026.

## Alternativas

Seguir con la imagen de MinIO de Chainguard, congelada sobre un proyecto archivado; SeaweedFS o Garage, que cambian la API de administración y la operación; S3 gestionado del proveedor europeo solo para el SaaS, que rompe la paridad con el on-premise.

## Consecuencias

Cambio acotado a deploy/compose y documentación: imagen pgsty/silo con release fijada, contenedor de inicialización de cubos con mcli y healthcheck con mcli ready. Licencia AGPLv3 igual que MinIO, sin efecto sobre el código propio porque se consume como servicio aparte. Riesgo nuevo en el tablero: dependencia de imágenes de terceros sin mantenimiento, con señal medible. El bundle on-premise de la fase 3 hereda la imagen y su verificación de firmas.
